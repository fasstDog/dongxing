# 技术与设计拍板（负责人，2026-09-22）

用户授权负责人直接拍板。产品须达到可对外演示的保真度。开发**禁止造轮子**，优先成熟开源框架/组件。

## 头部枢纽（玩法内容锁定）

北京、上海、广州、深圳、成都、重庆、武汉、杭州、郑州、西安、兰州、西宁。

每城维护 3～6 个「怎么玩」POI（距车站、建议游玩时长、是否赶得回）。详见 [`hubs.md`](./hubs.md)。

## 技术原则

| 层 | 选型原则 |
|----|----------|
| Web 原型 UI | Vant 或 TDesign Mobile（CDN/npm），不自研设计系统；**HTML 原型已冻结** |
| 微信小程序 | 微信原生运行时 + Vant Weapp（正式客户端之一；**非** RN/Alita 路径） |
| 手机 App | **官方 React Native** → iOS + Android（正式客户端之一）；与小程序共享 TS 契约/API/可抽出逻辑；组件库择成熟开源 |
| 非交付范围 | Windows/macOS/Web/tvOS/Linux、Proton Native、Alita 等社区扩展不是懂行产品承诺 |
| 规则引擎 | **全栈 TypeScript / Node**；禁止新增 Python |
| 数据 | **目标为合规真源**；`source:"mock"` 仅作实现/测试夹具与演示降级；密钥不进仓；禁止违规爬取 |
| 地图/接驳 | 优先官方/合规 SDK，不自研路网 |

## 产品不变（最终交付边界）

只推荐不卖票；三主卡（最省钱/最快/最综合）+ 更多；怎么去·为什么·怎么玩·外链购票；出计划程序算，模型不编车次票价；正式客户端仅两端 = 微信小程序 + 官方 React Native App（iOS + Android）。
