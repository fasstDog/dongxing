# 邪修交通 · 产品需求整理（截至 2026-09-22）

> 本文汇总当前已对齐的产品设想，供设计 / 开发对照。变现策略已讨论但明确「先把产品设计好」，下文仅附录备忘。

---

## 1. 一句话定位

输入出发地与目的地（可选日期、可选路径城市），推荐比直达更聪明的高铁 / 动车 / 飞机组合走法；讲清楚怎么去、为什么这样推；换乘时间长则告诉你怎么玩。**只推荐路线，不卖票**；购票跳转 12306 / 航司 / OTA。

心智：**帮你找到直达之外那条更聪明的路。**

---

## 2. 问题与机会

- 直达贵、绿皮慢；高铁换乘、空铁混搭常更划算，但大平台默认推直达或官方联运，邪修组合要用户自己拼。
- 抖音等已有大量「邪修路线」种草（如徐州→拉萨），缺一个把「怎么走 + 为什么 + 中转怎么玩」结构化的工具。
- 竞品分层：12306/航司空铁联运偏正规一票制；智行等中转偏铁路联程；灵犀出行、优途 AI、个人项目偏早期。成熟「以省钱邪修 + 窗口玩」为主产品的小程序仍少。

---

## 3. 目标用户（MVP）

- 价格敏感，愿意多换乘一次
- 时间稍宽裕，能接受「多几小时换更低价 / 更好坐」
- 被邪修内容种草，但不想自己查拼

暂不主打：商务极致准点、带老幼零容错、国际联程。

---

## 4. 核心原则

1. 默认给出 **3 个主方案**：最省钱 / 最快 / 最综合；下方提供更多方案。
2. 每条方案固定四块：**怎么去 · 为什么 ·（可选）怎么玩 · 去外链购票**。
3. 换乘不够长，不硬推景点。
4. 价格、时刻标「参考」，以购票平台为准。
5. 不做卖票、订单、支付、抢票。
6. **出计划由程序 / 规则引擎完成**；模型若接入，只做文案润色或口语偏好解析，**不生成车次与票价**。

---

## 5. 功能需求

### 5.1 查询输入

| 字段 | 必填 | 说明 |
|------|------|------|
| 出发地 | 是 | 城市 / 站点 |
| 目的地 | 是 | 城市 / 站点 |
| 出发日期 | 否 | 可「灵活」 |
| 路径城市 | 否 | 可多个、**有序**；用户指定必经途经点 |

- 不填路径城市 → **自动模式**：系统选枢纽并生成组合。
- 填写路径城市 → **指定路径模式**：按 `出发 → 途经1 → … → 途经n → 到达` 分段拼方案，不再自动换枢纽。
- MVP：途经最多 **2～3** 个；支持添加 / 删除 / 调序（调序可 MVP 或紧随）。

### 5.2 结果：三主卡 + 更多

**三主卡**

- **最省钱**：参考总价最低（建议加最长总时长上限，避免极端硬座方案）
- **最快**：门到门总时长最短
- **最综合**：价格、时长、换乘次数、「屁股友好」（卧铺占比、单段最长久坐）加权

指定路径模式下，三主卡是**同一路径**下不同交通方式 / 班次组合，而不是换其它城市。

**更多方案**：可按省钱 / 省时 / 少换乘（及可选「屁股友好」）筛选；点进同一套详情。

结果页可提供切换：**按你的路径** ↔ **试试系统自动邪修**（有途经时）。

### 5.3 方案卡片与详情字段

每张卡 / 详情需包含：

1. **怎么去**：分段时间轴（方式、站点、参考时刻、参考价、建议席别、段时长）；换乘节点标注同站 / 同城、缓冲时长、接驳提示。
2. **为什么这样做**：人话说明（比直达省/贵多少、多/少多久、票好不好抢、舒适度、若指定途经则说明「因你指定经某某」）。
3. **换乘怎么玩**：仅当缓冲达到阈值；POI 名称、距车站、建议游玩时长、是否赶得回。
4. **去购票**：按段跳转外链（参数带好站点与日期）；本产品不出票、不收款。

### 5.4 「怎么玩」出现规则

| 条件 | 行为 |
|------|------|
| 同站缓冲 ≥ 约 2 小时 | 偏休息 / 站内或极近 |
| 同城缓冲 ≥ 约 3 小时 | 可推 1～2 个景点 |
| 过夜或 ≥ 约 6 小时 | 可推半日玩（短住入口可预留） |
| 低于阈值 | 只提示休息与接驳，不硬推玩 |

MVP 枢纽玩法内容：先人工维护约 **8～12 个头部枢纽**（如北京、上海、广州、深圳、西安、成都、重庆、武汉、郑州、兰州、西宁、昆明）；其余中转城可只显示接驳。

### 5.5 明确不做（MVP）

卖票、支付、账号体系、抢票、官方联运一票制履约、国际线、复杂多日行程编辑器、社区 UGC、强推广告；2 次以上中转默认不进三主卡（可仅进「更多」或暂不做）。

---

## 6. 信息架构与主流程

**页面**：首页查询 → 结果列表（三主卡 + 更多）→ 方案详情（含枢纽玩法）→ 关于 / 免责声明。

**主流程**：

```
输入出发、到达（可选日期、可选有序途经）
  → 生成方案
  → 结果页三主卡
  → 详情（怎么去 / 为什么 / 怎么玩）
  → 分段「去购票」跳转外链
  → 或「更多方案」列表
```

---

## 7. 后台：如何出计划

**原则：程序算计划；模型可选当讲解员。**

流水线：

1. **取数**：火车 / 航班时刻与参考价（合规数据源）；直达作对照。
2. **定枢纽**  
   - 自动模式：规则候选枢纽（表或密度启发式）  
   - 指定路径：用户途经即枢纽链
3. **组合枚举**：分段查询；校验最小换乘时间；MVP 优先 **1 次中转**（指定途经时按段数，但限制途经个数）。
4. **打分**：产出最省钱 / 最快 / 最综合 + 更多列表。
5. **文案**：模板填「为什么」；POI 表填「怎么玩」；模型仅可选润色或解析「便宜就行 / 屁股舒服」等偏好。

**规则引擎难度判断**：打分与三主卡好写；难点在数据接入、同城换乘保守估时、边界 case 与缓存。MVP 可用死枢纽表 + 粗阈值 + 先 mock 再接真接口；先约 5 条热门线路（含徐州→拉萨）人工对答案再扩城。

## 8. 覆盖范围与开发量（粗估）

| 范围 | 粗估 |
|------|------|
| MVP：约 30～50 城，有限数据 / 死枢纽 | 约 1～2 人 × 4～8 周 |
| 可用全国版：地级市车站/机场、真数据、1 次中转 | 约 3～5 人 × 4～6 个月 |
| 较稳全国版 | 约 5～8 人 × 6～12 个月 |
| 镇/景区门牌 + 多段接驳 | 更长，内容与数据成本陡增 |

对外可宣传「全国能查」；对内建议：**站点逐步全国，玩法与精细换乘先头部城市**。路径：50 城跑通 → 地级市全覆盖 → 再谈乡镇接驳。

---

## 9. 成功标准（产品）

新用户从打开到看懂一个方案约 **30 秒内**；能说清「为什么不选直达」；愿意点至少一次外链购票或复制行程。

## 10. 样例场景（已用于对齐）

**徐州 → 拉萨**（示例卡片思路，价格为公开参考量级）：

- 方案 A：直达 Z 字头过路车，总时长很长；硬座便宜但「屁股」差，硬卧贵且过路票难抢。
- 方案 B：经西宁拆两段（推荐向）；后半段始发进藏，票与舒适度往往更好；窗口可玩塔尔寺等。
- 方案 C：经西安（高铁 + 火车或飞机）；可玩可飞，缓冲够则推兵马俑等。

展示字段：总价区间、总时长、相对直达、屁股分、换乘能否玩、分段外链。
