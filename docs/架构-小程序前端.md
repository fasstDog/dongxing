> 对齐总架构 [`邪修交通-系统架构设计_v1.0.md`](./邪修交通-系统架构设计_v1.0.md)（懂行总架构 v1.0）第1/3/8章  
> 产品边界见 [`架构-产品与体验.md`](./架构-产品与体验.md)  
> 引擎契约见 [`架构-规则引擎.md`](./架构-规则引擎.md) 与 `api-plans-contract.md`  
> 技术栈锁定见 [`ADR-技术栈-TS与多端.md`](./ADR-技术栈-TS与多端.md)、[`ADR-客户端-Taro一码多端.md`](./ADR-客户端-Taro一码多端.md)、[`ADR-客户端-ReactNative.md`](./ADR-客户端-ReactNative.md)  
> **根目录 HTML/Vue 原型冻结。正式客户端仅两端：微信小程序 + React Native App（iOS + Android）；生产 UI 源 = Taro + React + TS（`frontend/taro-app/`）。共享契约 / 引擎 API / 同一 UI 源。禁止 Alita。`frontend/miniprogram/` 为 transitional。**

## 0. 多端范围

| 端 | 状态 | UI / 技术 | 与引擎关系 |
|----|------|-----------|------------|
| **微信小程序** | 正式交付 | **Taro → weapp**（`frontend/taro-app/`）；页栈见 §2 | 消费 `POST /v1/plans/search`（`api-plans-contract`） |
| **手机 App** | 正式交付 | **Taro → React Native** → **iOS + Android**（同一 `frontend/taro-app/`） | **同一** `api-plans-contract`；禁止私造班次 |
| `frontend/miniprogram/` | **过渡** | 微信原生 + `@vant/weapp`；Taro weapp 可运行前保留演示 | 同契约；标注 transitional |
| Web `prototype/` | 冻结示意 | Vue3+Vant4 CDN | 不演进 |

原则：多端只做展示与导航；出计划只在引擎。契约破坏性变更须同步两端。生产 UI **一码**（Taro）。  

**非交付范围：** Windows / macOS / Web / tvOS / Linux、Proton Native、Alita 等不是懂行承诺。

## 1. 职责与红线

| 做 | 不做 |
|----|------|
| 查询 → 三主卡 → 详情 → 关于 | 卖票 / 支付 / 登录 / 账号 |
| 加载 / 空 / 失败三态（规范文案） | 在端上枚举 MCT、编造车次票价 |
| 薄适配层：`PlansSearchResponse` → UI | 直连供应商 API、嵌入密钥 |
| 外链购票示意（12306/OTA） | 自研设计系统；在端上卖票 |
| Taro 一码（weapp + RN） | Alita；永久双套业务 UI |

原则：**程序算出计划，前端只展示与导航。** `ok:false` 必须走空/失败态，禁止静默编造方案。

## 2. 页面栈（Taro 与过渡小程序对齐）

```
pages/query     出发/到达/可选日期/有序途经(≤3) + 样例 OD + 演示三态开关
pages/results   加载 → 三主卡(cheap/fast/balanced) + 更多；空/失败三态
pages/detail    怎么去时间轴 · 为什么 ·（可选）怎么玩 · 分段外链购票
pages/about     只推荐不卖票 · 免责 · 数据说明
```

信息架构与文案以产品架构 / `空态与文案规范` 为准；交互细节见 `小程序-查询与三主卡交互要点.md`。RN App 复用同一信息架构，不必复制微信组件。

## 3. 与引擎/数据的边界

```
[小程序 / RN App]  --POST /v1/plans/search-->  [引擎服务 · TS/Node]
                  <-- PlansSearchResponse --
                             ↑
                       adapters → Leg[] / TransferPlay
```

| 口径 | 前端数据来源 |
|------|----------------|
| **最终交付** | HTTPS `POST /v1/plans/search`，响应符合 `api-plans-contract`；小程序与 RN App 同一契约 |
| **工程过渡** | 开发可用本地 `frontend/miniprogram/data/plans-*.json` 或 mock 服务；语义与真 API 一致，不另定产品字段 |
| **真源切换** | 仅发生在引擎侧；各端适配层字段不变 |

共享类型：`packages/shared`（`@dongxing/shared`）— `Leg` / `TransferPlay` / `PlansSearch*`；小程序与 RN App / 引擎共用。可抽出业务逻辑进共享包；UI 仍分端。

适配层（小程序 `utils/adapt-plans.js`；RN App 侧等价模块）：

- 输入：契约 snake_case（`main[]` / `more[]` / `timeline` kind=`leg|xfer`）
- 输出：页面 camelCase；`service_ref` **原样透传**，不改写车次
- pipeline 槽位 `cheapest|fastest|balanced` 与 API `cheap|fast|balanced` 在适配层归一

## 4. 技术选型（拍板）

| 项 | 选择 |
|----|------|
| 语言 | **TypeScript**（新代码）；与引擎同方向 |
| 生产 UI 源 | **Taro 3/4 + React + TS**（`frontend/taro-app/`）→ weapp + RN(iOS/Android) |
| 过渡小程序 | `frontend/miniprogram/` 微信原生 + `@vant/weapp`（可演示，待退役） |
| 手机 App | Taro RN 目标（iOS + Android）；禁止自研设计系统；禁止 Alita |
| 状态 | 页内 state / 简易全局；默认不引入重型全局 store |
| 网络 | Taro `request` / 平台 HTTP；超时/非 2xx → 失败态文案；可回落本地 mock |

## 5. 组件与三态（小程序）

- 查询：`van-field` / `van-button` / `van-switch` / `van-tag`
- 结果：`van-loading` / `van-empty` / 卡片列表；空态提供样例 OD 一键填入
- 详情：时间轴（火车/飞机样式）+ why + play + 购票 Toast/外链
- 关于：免责与「价格时刻均为参考、不保证有票」

加载时长演示约 600–900ms；正式接 API 后以真实 RTT 为准，文案不变。RN App 三态文案与小程序对齐 `空态与文案规范`。

## 6. 落地节奏（工程分步，非产品砍范围）

最终交付：两端均消费同一 `PlansSearchResponse`；完整查询→三主卡→详情→关于；三态齐全；外链购票。下列仅为实现顺序：

| 节奏 | 工程交付 |
|------|----------|
| R0 | 过渡小程序四页 + 契约对齐 mock；Taro 骨架落地 |
| R1 | Taro 接 `POST /v1/plans/search`（含 mock 回落）；weapp 可预览 |
| R2 | Taro RN(iOS/Android) 目标可跑；真源在引擎侧切换 |
| R3 | 微信提审 / App 商店发布；退役 `frontend/miniprogram/`；仍不引入卖票 |

## 7. 非目标

- 为 RN App / 小程序维护两套互斥 API  
- 用 RN / Alita / 其它跨端方案「编译出」微信小程序  
- 将 Win / macOS / Web / tvOS / Linux 纳入产品交付
