# 架构 · 客户端（微信小程序 + 手机 App）

> 对齐总架构 [`邪修交通-系统架构设计_v1.0.md`](./邪修交通-系统架构设计_v1.0.md)（懂行总架构 v1.0）第1/3/8章  
> 产品边界见 [`架构-产品与体验.md`](./架构-产品与体验.md)  
> 引擎契约见 [`架构-规则引擎.md`](./架构-规则引擎.md) 与 `api-plans-contract.md`  
> 技术栈锁定见 [`ADR-技术栈-TS与多端.md`](./ADR-技术栈-TS与多端.md)  
> **根目录 HTML/Vue 原型冻结。正式客户端 = 微信小程序（Vant Weapp）+ 手机 App；共享同一 API/契约，不止小程序。**

## 0. 多端范围

| 端 | 状态 | UI / 技术 | 与引擎关系 |
|----|------|-----------|------------|
| **微信小程序** | 正式交付 | `@vant/weapp`；页栈见 §2 | 消费 `POST /v1/plans/search`（`api-plans-contract`） |
| **手机 App** | 正式 · 规划 | TS 技术栈（壳/组件待定）；**信息架构与三主卡对齐小程序** | **同一** `api-plans-contract`；禁止私造班次 |
| Web `index.html` | 冻结示意 | Vue3+Vant4 CDN | 不演进 |

原则：多端只做展示与导航；出计划只在引擎。契约破坏性变更须同步小程序与 App。

## 1. 职责与红线

| 做 | 不做 |
|----|------|
| 查询 → 三主卡 → 详情 → 关于 | 卖票 / 支付 / 登录 / 账号 |
| 加载 / 空 / 失败三态（规范文案） | 在端上枚举 MCT、编造车次票价 |
| 薄适配层：`PlansSearchResponse` → UI | 直连供应商 API、嵌入密钥 |
| 外链购票示意（12306/OTA） | 自研设计系统（小程序只用 `@vant/weapp`） |

原则：**程序算出计划，前端只展示与导航。** `ok:false` 必须走空/失败态，禁止静默编造方案。

## 2. 页面栈（小程序现实现；App 对齐）

```
pages/query     出发/到达/可选日期/有序途经(≤3) + 样例 OD + 演示三态开关
pages/results   加载 → 三主卡(cheap/fast/balanced) + 更多；空/失败三态
pages/detail    怎么去时间轴 · 为什么 ·（可选）怎么玩 · 分段外链购票
pages/about     只推荐不卖票 · 免责 · 数据说明
```

信息架构与文案以产品架构 / `空态与文案规范` 为准；交互细节见 `小程序-查询与三主卡交互要点.md`。App 复用同一信息架构，不必复制微信组件。

## 3. 与引擎/数据的边界

```
[小程序 / App]  --POST /v1/plans/search-->  [引擎服务 · TS/Node]
               <-- PlansSearchResponse --
                          ↑
                    adapters → Leg[] / TransferPlay
```

| 口径 | 前端数据来源 |
|------|----------------|
| **最终交付** | HTTPS `POST /v1/plans/search`，响应符合 `api-plans-contract`；小程序与 App 同一契约 |
| **工程过渡** | 开发可用本地 `miniprogram/data/plans-*.json` 或 mock 服务；语义与真 API 一致，不另定产品字段 |
| **真源切换** | 仅发生在引擎侧；各端适配层字段不变 |

共享类型：`packages/shared`（`@dongxing/shared`）— `Leg` / `TransferPlay` / `PlansSearch*`；小程序 npm 依赖 `file:../packages/shared`，与 App/引擎共用。

适配层（小程序 `utils/adapt-plans.js`；App 侧等价模块）：

- 输入：契约 snake_case（`main[]` / `more[]` / `timeline` kind=`leg|xfer`）
- 输出：页面 camelCase；`service_ref` **原样透传**，不改写车次
- pipeline 槽位 `cheapest|fastest|balanced` 与 API `cheap|fast|balanced` 在适配层归一
- 目标：共享 TS 类型（monorepo `packages/contracts`）

## 4. 技术选型（拍板）

| 项 | 选择 |
|----|------|
| 语言 | **TypeScript**（新代码）；与引擎同方向 |
| 小程序运行时 | 微信小程序 |
| 小程序 UI | `@vant/weapp`（禁止自研组件库） |
| 手机 App | 规划；TS；组件库另择成熟开源，禁止自研设计系统 |
| 状态（小程序） | 页内 data + `globalData.lastQuery`；默认不引入全局 store（可按复杂度演进） |
| 网络 | 小程序 `wx.request`；App 平台 HTTP；超时/非 2xx → 失败态文案 |

## 5. 组件与三态（小程序）

- 查询：`van-field` / `van-button` / `van-switch` / `van-tag`
- 结果：`van-loading` / `van-empty` / 卡片列表；空态提供样例 OD 一键填入
- 详情：时间轴（火车/飞机样式）+ why + play + 购票 Toast/外链
- 关于：免责与「价格时刻均为参考、不保证有票」

加载时长演示约 600–900ms；正式接 API 后以真实 RTT 为准，文案不变。App 三态文案与小程序对齐 `空态与文案规范`。

## 6. 落地节奏（工程分步，非产品砍范围）

最终交付：两端均消费同一 `PlansSearchResponse`；完整查询→三主卡→详情→关于；三态齐全；外链购票。下列仅为实现顺序：

| 节奏 | 工程交付 |
|------|----------|
| R0 | 小程序四页壳 + 契约对齐的本地/预导出 JSON（开发便利，产品语义同真 API） |
| R1 | `adapt-plans` 接 `POST /v1/plans/search`；预导出仅作离线降级；App 工程骨架 |
| R2 | 真源在引擎侧切换，各端适配层字段不变；性能与空态验收 |
| R3 | 小程序提审 / App 正式发布；体验优化（仍不引入卖票） |

## 7. 非目标

- 继续演进根目录 `index.html` Vue 原型  
- 在客户端内写死假车次当「引擎」  
- 支付、会员、抢票、官方联运履约  
- 为 App / 小程序维护两套互斥 API
