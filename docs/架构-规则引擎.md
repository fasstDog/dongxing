# 架构 · 规则引擎

> 状态：架构文档阶段（2026-09-23）  
> 范围：可用系统的方案生成与打分，**不是**静态 HTML/Vue 原型加功能。  
> 正式前端：微信小程序（Vant Weapp）只消费本层产出的 plans；本层**程序算出计划**，禁止模型生成车次与票价。

相关文档：

- [`api-plans-contract.md`](./api-plans-contract.md) — 方案生成请求/响应约定  
- [`架构-数据与内容.md`](./架构-数据与内容.md) — 适配器、`Leg` / `TransferPlay`  
- [`架构-产品与体验.md`](./架构-产品与体验.md) — 三主卡、途经、红线  
- 实现入口：`engine/pipeline.js`、`engine/score.js`、`engine/mct.js`、`engine/adapters/`

## 1. 在系统中的位置

```
小程序查询（from/to/date/vias）
        │
        ▼
  POST /v1/plans/search（或本地 pipeline.searchPlans）
        │
        ├─ adapters.searchLegs（train + flight）
        ├─ data/hub-pois.json（TransferPlay）
        │
        ▼
  定链 → 枚举 → MCT → 挂玩法 → 打分 → 三主卡 + 更多
        │
        ▼
  plans JSON（snake_case；小程序适配层可转展示）
```

| 做 | 不做 |
|----|------|
| 组合枚举、粗 MCT、cheap/fast/balanced 打分 | 卖票、余票、库存 |
| 产出三主卡 + 更多 + `why_facts` / 口语 why 模板 | 模型编车次号/票价 |
| 导出 `data/plans-*.json` / `data/mock/plans-*.json` | 维护 POI 文案（归数据） |
| 与适配器契约对齐（`date` / `after_at`） | 静态原型加交互 |

## 2. 流水线（稳定步骤）

顺序固定，实现可换语言，**不可跳步让模型填班次**：

1. **取腿**  
   - `adapters/index.searchLegs({ from, to, date?, after_at? })`  
   - 合并 train + flight；真源替换 mock 时契约不变。  
   - **首段**可用 `date`；**续段**必须 `after_at = prev.arr_at`。

2. **定链**  
   - 无途经 → 自动：`from → hub → to`（`HUBS_MVP` + 可选 `extraHubs`，如成渝遂宁/内江）  
   - 有途经 → 用户有序链：`from + vias + to`（途经 ≤ 3）  
   - MVP 默认 **最多 1 次中转**进三主卡。

3. **枚举 + MCT**  
   - 各 hop 取腿后做笛卡尔积（有上限）  
   - `mct.js`：同站 / 同城最小缓冲；不达标丢弃  

4. **挂「怎么玩」**  
   - 仅当 `buffer_hours >= TransferPlay.min_buffer_hours`  
   - 非 12 城枢纽可不维护 POI，只保留接驳 tip  

5. **打分选主卡**（`score.js`，分越低越好）  
   - **最省钱**：参考总价为主（可加时长上限防极端）  
   - **最快**：门到门总时长为主  
   - **最综合**：价 + 时长 + 换乘 + 单段久坐；**空铁进最快**，综合偏铁路卧铺/可玩窗口  

6. **文案**  
   - 引擎填 `why_facts` + 口语模板；产品可改字段验收  
   - 模型若接入：只润色，不改数值与 `service_ref`

## 3. 对外 API 形状

以 [`api-plans-contract.md`](./api-plans-contract.md) 为准。摘要：

| | |
|--|--|
| 请求 | `from_city`, `to_city`, `date_flexible` / `date`, `vias[]`, `path_mode` |
| 响应 | `ok`, `main`（cheap/fast/balanced）, `more`, `direct_baseline`, `meta` |
| 方案卡 | 时间轴 `timeline`（leg / xfer）、`why` / `why_detail`、`play`、`buy_legs` |
| 纪律 | `service_ref` / 价格时刻来自 `Leg`；`meta.no_realtime_inventory: true` |

本地演示（非服务化前）：

```bash
node engine/search-pipeline-demo.js
node engine/export-plans-with-flight.js          # all
node engine/export-plans-with-flight.js cd-cq    # 单 OD
```

服务化后：同一 `searchPlans` 挂 HTTP；小程序只打正式 API，不读仓库内 JSON（开发期可读 mock）。

## 4. 模块边界

| 模块 | 职责 |
|------|------|
| `adapters/*` | 取 `Leg[]`（数据侧契约；引擎不解析源站 HTML） |
| `mct.js` | 换乘窗规则与校验 |
| `score.js` | 纯打分与 `pickMainCards` |
| `pipeline.js` | 定链、枚举、挂玩法、组装方案对象 |
| `export-plans-with-flight.js` | 多 OD mock 导出（开发/验收用） |

配置建议（实现阶段）：

- MCT 阈值、综合权重、`CHEAP_MAX_DURATION` → 可配置常量，不写死在业务分叉里  
- `HUBS_MVP` 与玩法表分离；`extraHubs` 仅扩枚举、不自动开玩法  

---

## 5. 与各端边界

| 对方 | 引擎依赖 | 引擎不碰 |
|------|----------|----------|
| **数据** | `Leg` / `TransferPlay` / adapters | 源站选型、POI 撰写、密钥 |
| **产品** | 三主卡语义、途经规则、人话验收 | 改红线去卖票 |
| **小程序** | 消费 plans API；展示三态 | 本地编班次、改打分 |
| **发布** | 导出命令与版本说明 | 替引擎改权重 |

静态 Web 原型：只作示意；**禁止**再为原型加引擎旁路逻辑。

---

## 6. 里程碑（实现阶段再拆任务）

| 阶段 | 目标 |
|------|------|
| **M0（现仓）** | mock adapters + pipeline + 多样例 plans 导出；文档与契约齐 |
| **M1** | `searchPlans` 服务化（Node）；小程序打真 API；仍 mock/缓存降级 |
| **M2** | 真源 adapters 切入；权重/MCT 配置化；观测（耗时、空结果率） |
| **M3** | 多中转进「更多」、全国枢纽策略；仍坚持程序算、不卖票 |

验收不变量：

1. 任意方案的车次/航班参考文案可追溯到某条 `Leg.service_ref`  
2. 无「实时有票」承诺  
3. 空窗不达标不出现硬推玩法
