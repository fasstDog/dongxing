## 1. 在系统中的位置

```
合规数据源 / mock 文件
        │
        ▼
  adapters（train.* / flight.*）
        │  Leg[]
        ▼
  规则引擎（枢纽链 → MCT → 打分 → plans）
        │
        ▼
  小程序（只展示；购票外链）
```

并行内容流：

```
data/hub-pois.json（TransferPlay）
        │
        ▼
  引擎仅在 buffer ≥ min_buffer_hours 时挂到换乘节点
```

本层职责：

| 做 | 不做 |
|----|------|
| 选型与接入合规火车/航班源 | 违规爬取、模拟登录 |
| 输出定稿 `Leg`；维护 `TransferPlay` | 生成车次号/票价（含模型） |
| 缓存、降级、`source`/`as_of` | 卖票、库存、余票承诺 |
| 密钥走环境变量 / 密钥管理 | 密钥进仓、进小程序包 |

## 2. 适配器契约（稳定面）

目录：`engine/adapters/`

| 模块 | 行为 |
|------|------|
| `train.mock.js` | `search({ from_city, to_city, date?, after_at? }) → Leg[]`（仅 train） |
| `flight.mock.js` | 同契约（仅 flight）；默认可扫 `data/mock/legs-*.json` |
| `train.<vendor>.js` / `flight.<vendor>.js` | 后续真源；同契约，密钥仅 env |
| `index.js` | 合并 train+flight，供 pipeline 取腿 |

约定：

1. **首段**可用 `date` 平移日历；**续段**必须用 `after_at: prev.arr_at`，禁止两段都传同一 `date`（overnight MCT 会穿帮）。  
2. 真源与 mock **同一 Schema**，引擎无感切换。  
3. MVP 缓存：**单机内存 TTL**（见 `data-sources.md` §8）；多实例后再 Redis。  
4. 降级：真源 → 未过期缓存 → mock → 可解释空结果（前端三态）。

## 3. 内容资产布局

```
data/
  hub-pois.json              # TransferPlay 独立表（按 hub_city 查）
  mock/
    legs-*.json              # 分段腿原料（徐拉/沪蓉/京汉/成渝…）
    plans-*.json             # 引擎导出的方案（本层不手写三主卡）
  plans-*.json               # 前端/小程序可读副本（由引擎导出同步）
docs/schemas/                # JSON Schema
```

样例 OD（mock 覆盖，非产品承诺全国）：

| OD | 腿文件 | 说明 |
|----|--------|------|
| 徐州→拉萨 | `legs-xuzhou-lhasa.json` | 长线 + 西宁玩法 + 西安空铁 |
| 上海→成都 | `legs-shanghai-chengdu.json` | 经武汉/西安 + 直飞 |
| 北京→武汉 | `legs-beijing-wuhan.json` | 京广短途 |
| 成都→重庆 | `legs-chengdu-chongqing.json` | 成渝短途；遂宁/内江为 extraHubs |

12 城以外的中转城：**可以有腿，不维护玩法表**，引擎不硬推景点。

## 4. 「怎么玩」内容规则

- 表：`TransferPlay`，独立于 `Leg`。  
- 门槛：与产品一致（约同站 ≥2h / 同城 ≥3h / 半日 ≥6h）。  
- 每城目标 3～6 条；西宁为样板。  
- 后续若接地图 POI API：仅官方/合规 SDK，时长与是否赶得回仍需审校。

---

## 5. 向可用系统演进（数据侧里程碑）

1. **M0（当前）** — mock 腿 + TransferPlay + adapters；引擎导出 plans；小程序读 JSON/将来 API。  
2. **M1** — `TrainLegProvider` 接一家合规火车源；热门 OD 对照人工答案；密钥与观测就位。  
3. **M2** — `FlightLegProvider`；空铁「最快」走真源+降级。  
4. **M3** — 覆盖扩城、缓存分层、玩法表按枢纽运营更新。

静态 Web 原型：**冻结**，仅作界面示意，不再为本层「演示方便」改原型交互。

## 6. 与邻层接口摘要

| 邻层 | 输入给对方 | 期望对方 |
|------|------------|----------|
| 规则引擎 | `Leg[]`、`TransferPlay[]`、`source`/`as_of` | 不改写 `service_ref`/票价；续段用 `after_at` |
| 小程序 | （经引擎）plans；本层不直连 UI | 价格时刻标参考；失败走三态 |
| 发布 | 无运行时依赖 | README 链 adapters 与导出命令即可 |
