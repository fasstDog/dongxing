## 2. 火车（第一优先）

### 2.1 选型原则（合规优先）

按推荐顺序评估（落地前须完成商务/法务确认，本文不绑定未签约供应商）：

1. **已签约的数据服务商 / 开放平台**（合同允许火车时刻 + 参考价，有 SLA 与用途条款）  
2. **铁路或地方政府公开、允许商用的开放数据**（若有；需核对许可证）  
3. **过渡期继续 `source: "mock"`**（`backend/data/mock/legs-*.json`），产品与引擎并行，不挡演示  

明确不做：模拟登录、绕过验证码、批量抓取购票页 HTML/私有接口。

### 2.2 接入形态（与引擎约定）

- 适配器输出 **定稿 `Leg`**（见 `docs/schemas/leg.schema.json`）  
- 查询键建议：`from_city`/`to_city` 或中文站名 + 日期；站码后续再加  
- `price_ref_cny`：代表价（元整数）；有区间则填 `price_min_cny` / `price_max_cny`  
- 每条腿写 `source`（如服务商 id）与 `as_of`（拉取或缓存写入时刻）

### 2.3 缓存策略（火车）

| 层 | TTL（建议起点） | 内容 |
|----|-----------------|------|
| L1 进程内 | 5–15 min | 热点 OD 当日查询 |
| L2 共享缓存（Redis 等） | 1–6 h | 按 OD+日期(+大致时段) |
| L3 快照文件 / 对象存储 | 12–24 h | 预热热门线；可作降级读 |

- 价格波动大：TTL 偏短；时刻相对稳：可略长。  
- 缓存键不含密钥；响应可存，凭证不可存盘明文进仓。  
- `as_of` 必须随缓存条目更新，前端展示「参考，以购票平台为准」。

## 3. 航班（第二优先）

用于「最快」等空铁混搭，非全国机票比价引擎。

1. **航司 / 聚合商官方 API 或已签约源**  
2. 无合约前：**mock 航班腿**（已有徐州→西安→拉萨示例）  
3. 同样禁止违规爬取 OTA。

缓存：机票价更易变，L1/L2 TTL 更短（如 5–30 min / 1–2 h）；降级时宁可返回「无实时价，仅示意时长」或回退 mock，也不编造航班号当真实可售。

---

## 4. 降级阶梯

引擎取数顺序建议：

```
真源 API（成功且未过期缓存）
  → 未过期 L2/L3 缓存（source 保留原源或标记 cache）
    → 预置 mock 腿（source: "mock"）
      → 返回可解释错误（无可用腿；前端空态文案）
```

规则：

- **禁止**在降级路径用模型生成 `service_ref` / 票价。  
- mock 与真源字段同一 Schema，便于引擎无感切换。  
- 部分成功：有火车 mock + 无航班时，允许只出铁路方案，不硬凑空铁。
