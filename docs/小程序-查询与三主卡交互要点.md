# 客户端 · 查询 / 三主卡 / 详情交互要点（懂行）

> 最终交付设计（微信小程序 + **官方 React Native** App · iOS/Android 共用产品语义；UI / 运行时分端）。小程序组件参考 **Vant Weapp**；RN App 另选成熟开源组件库。**RN/Alita 不是小程序交付路径。**  
> 对照 [`架构-产品与体验.md`](./架构-产品与体验.md)、[`空态与文案规范.md`](./空态与文案规范.md)。**勿发明卖票 / 登录 / 支付流程。**  
> 静态 Web 原型仅示意，不再加功能。

---

## 1. 交付范围（最终）

| 包含 | 明确不做（产品红线，非分期借口） |
|------|----------------------------------|
| 查询 → 三主卡结果 → 方案详情 → 关于/免责 | 支付、登录、订单、抢票、本产品出票收款 |
| 加载 / 无方案 / 失败三态 | 为某一端另写一套业务规则或打分 |
| 消费 `POST /v1/plans/search`（及同等契约） | 模型编造车次 / 票价 |
| 按段外链购票（12306 / 航司 / OTA） | |

工程可用本地 mock 或回落 JSON 开发，但**产品定义以真 API + 完整页面栈为准**。

---

## 2. 产品锁定

- **只推荐路线，不卖票。**
- 购票仅 **外链**（说明跳转第三方）；本产品不出票、不收款。
- **无登录、无支付、无订单。**

---

## 3. 查询页

| 字段 | 必填 | 说明 |
|------|------|------|
| 出发地 | 是 | 城市 / 站点 |
| 到达地 | 是 | 城市 / 站点 |
| 出发日期 | 否 | 含「日期灵活」 |
| 途经城市 | 否 | **有序**，最多 **3**；支持增删与调序 |

校验失败 **一律留在查询页**（Toast），文案对齐 [`空态与文案规范.md`](./空态与文案规范.md)：

| 条件 | 文案 |
|------|------|
| 出发或到达为空 | 先填出发地和目的地 |
| 出发 = 到达 | 出发和到达不能是同一个地方 |
| 途经已满 3 再添加 | 途经最多 3 个（按钮优先禁用） |
| 途经与出发/到达重复 | 途经别和出发/到达重复 |

主按钮：**开始推荐**（或等价人话；避免对用户说「邪修」工程梗，除非品牌策略另定）。

---

## 4. 结果页 · 三主卡

三张主卡固定顺序：**最省钱 → 最快 → 最综合**；下方可有「更多方案」。

每卡信息层级（自上而下）：

1. **标题**：最省钱 / 最快 / 最综合  
2. **参考价**（标「参考」，不承诺有票）  
3. **总时长**  
4. **一句话为什么**（人话）  
5. **标识**：换乘 / 飞机 / 空铁等

### 三态

| 态 | 行为 / 文案要点 |
|----|-----------------|
| 加载 | 隐藏三主卡；「正在组合方案…」类人话 |
| 无方案 | 「这趟暂时拼不出方案」+ 原因（含不保证有票）+ 改条件 / 看示例 |
| 失败 | 「这趟没查到，多半是数据暂不可用」+ 再试一次 / 改条件 |

完整句见空态规范。样例 OD（徐拉 / 沪蓉 / 京广 / 成渝）作验收基线。

---

## 5. 方案详情

点主卡进入详情，须含：

1. **怎么去**（分段时间轴）  
2. **为什么**  
3. **怎么玩**（仅空窗达标；否则只休息/接驳）  
4. **去购票**（按段外链；明确本产品不卖票）

无效方案 id → 回结果或友好提示，不白屏。

---

## 6. 文案红线

- **不承诺有票**（禁用「一定有票 / 帮你买到」）。
- 价格、时刻一律标 **参考**，以购票平台为准。
- 换乘空窗不够长 → **不硬推怎么玩**。
- 统一短句：只推荐路线，不卖票。 / 价格、时刻都是参考，不保证有票。

---

## 7. 多端

同一套字段与红线；小程序与 RN App **不得**分叉产品语义。共享类型见 `@dongxing/shared`；契约以 `docs/api-plans-contract.md`（或仓内同等文件）为准。产品交付平台仅此两端（桌面/Web/tvOS/Alita 等非承诺）。
