## 1. 一句话定位

输入出发 / 到达（可选日期、有序途经），**程序规则引擎**给出最省钱 / 最快 / 最综合三主卡 + 更多方案；讲清怎么去、为什么；换乘空窗够长再讲怎么玩。**只推荐路线，不卖票**；购票跳转 12306 / 航司 / OTA。

---

## 2. 产品红线（不可破）

| 红线 | 说明 |
|------|------|
| 不卖票 | 无支付、无订单、无账号、无抢票 |
| 程序出计划 | 车次、时刻、参考价、换乘窗由引擎/数据产出；模型只可润色「为什么 / 怎么玩」文案 |
| 不编造 | 禁止模型生成车次号与票价 |
| 参考价/时刻 | 一律标明参考，以购票平台为准 |
| 空窗不够不硬推玩 | 低于阈值只提示休息/接驳，不硬塞景点 |

## 3. 信息架构（正式小程序）

```
查询页 → 结果页（三主卡 + 更多）→ 方案详情 → 关于 / 免责
         ↑ 加载 / 无方案 / 失败三态挂在结果层
```

### 3.1 查询

| 字段 | 必填 | 规则 |
|------|------|------|
| 出发地 | 是 | 城市 / 站点 |
| 目的地 | 是 | 城市 / 站点；不可与出发相同 |
| 出发日期 | 否 | 可「日期灵活」 |
| 有序途经 | 否 | 最多 3；可增删；途经不可与出发/到达重复 |

- 无途经 → **自动邪修**（系统选枢纽链）
- 有途经 → **按你的路径**分段；可提供切换「试试系统自动」

### 3.2 结果：三主卡 + 更多

- **最省钱 / 最快 / 最综合**：同一查询下的主推荐
- **更多**：同结构方案列表
- 指定途经时，三主卡默认在同一路径上比价/比时，不擅自换城

### 3.3 方案卡 / 详情固定块

1. **怎么去**：分段时间轴（方式、站点、参考时刻、参考价、段时长）；换乘节点标注同站/同城与空窗  
2. **为什么**：人话一句到两句（相对直达、舒适度、因你指定经某某）  
3. **怎么玩**（可选）：仅空窗达标；POI、距车站、建议时长、能否赶回  
4. **去购票**：按段外链；本产品不出票、不收款  

### 3.4 三态

对齐 [`空态与文案规范.md`](./空态与文案规范.md)：加载中、无方案、数据失败；查询校验失败用 Toast / 就地提示，不跳假结果。

## 4. 与各端边界

| 角色 | 负责 | 不负责 |
|------|------|--------|
| **产品体验** | 边界红线、信息架构、交互要点、人话口径与验收 | 打分实现、真数据接入、UI 组件库选型落地 |
| **规则引擎** | 取腿→枢纽/途经→MCT→打分→plans API | 界面、POI 文案撰写 |
| **数据内容** | 时刻/参考价源、缓存降级、枢纽怎么玩 POI 表 | 打分权重、页面结构 |
| **前端（小程序）** | 页面栈、Vant Weapp、消费 plans、三态与外链购票 | 改卖票闭环、自造车次 |
| **发布** | 文档入口、版本/tag、示意原型 vs 正式小程序说明 | 产品范围变更 |

静态 Web 原型：只读示意，实现以 `miniprogram/` + 本架构为准。

## 5. 验收样例（不阻塞架构）

| OD | 用途 |
|----|------|
| 徐州 → 拉萨 | 长途邪修、空铁、怎么玩 |
| 上海 → 成都 | 中长途、直飞 vs 换乘 |
| 北京 → 武汉 | 短途高铁 + 过夜便宜档 |
| 成都 → 重庆 | 短途高铁邪修、extraHub 不硬推玩 |

人话抽检以 plans 字段 + 小程序展示为准；引擎重导须带口语 `render_why`，避免盖回工程腔。
