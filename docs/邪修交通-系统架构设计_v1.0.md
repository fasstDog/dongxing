## 1. 架构总览

### 1.1 设计原则（12 条 · 机制化）

| # | 原则 | 机制化解释（可检查） |
|---|------|----------------------|
| P1 | **只荐不卖** | 系统不提供订单、支付、账号履约；「去购票」仅外链/Toast stub；任何 PR 引入收款能力直接拒审（§7.5） |
| P2 | **程序算计划** | 方案枚举、MCT、打分、三主卡挑选只走 `pipeline` + `mct` + `score`；`service_ref` / `price_ref_cny` **原样来自适配器**，引擎禁止改写或臆造 |
| P3 | **LLM 禁编班次票价** | 模型若接入，仅允许口语偏好解析或「为什么」文案润色；禁止输出/覆盖 `Leg.service_ref`、票价字段；默认关闭 LLM（§3.1 C7） |
| P4 | **窄腰宽边** | 引擎只消费统一 `Leg[]` / `TransferPlay`；火车/航班/未来真源一律经 Adapter 归一；前端只消费 `PlansSearchResponse` 形（§5） |
| P5 | **参考价可演示 + 真源为目标** | 设计目标为合规真源；无合约/降级时允许纯 `source:"mock"` 冒烟与演示（已拍板）；UI 必须展示「价格、时刻均为参考，以购票平台为准」 |
| P6 | **失败可解释** | 无腿 / MCT 不可行 / 校验失败 → 明确 `ok:false` + `reason`/`error.code` + 前端空态文案；**禁止静默编造方案** |
| P7 | **换乘阈值硬约束** | 同站 MCT 默认 60min、同城 180min；缓冲低于 `TransferPlay.min_buffer_hours` **不挂**「怎么玩」 |
| P8 | **三主卡契约** | 有方案时产出最省钱 / 最快 / 最综合（`cheap`/`fast`/`balanced`）；更多方案进 `more`；2 次以上中转默认不进三主卡（可进 `more`） |
| P9 | **密钥零入库** | 密钥仅环境变量 / 密钥托管；`.gitignore` 忽略 env；CR 拒绝含 Key 的 commit；公开仓不写供应商商务细节 |
| P10 | **禁止违规爬取** | 不得模拟登录、绕验证码、批量抓购票页；真源仅合规 API / 已签约渠道（§5.6） |
| P11 | **多端正式客户端** | 正式交付仅两端 = **微信小程序 + RN App（iOS+Android）**；**UI 源 = Taro 一码**；共享 `POST /v1/plans/search` 与契约；**禁止 Alita**；`frontend/miniprogram/` 过渡；`prototype/` 冻结；桌面/Web/tvOS 等非产品承诺 |
| P12 | **一处定义处处引用** | `Leg`/`TransferPlay` 以 Schema + `data-contract-mock.md` 为准；枢纽以 `hubs.md` 12 城为准；API 以 `api-plans-contract.md` 为准；术语见 §10.4 |

| 能力特征 | 归入 |
|----------|------|

## 2. 技术栈选型

> **锁定（2026-09-23）**：全栈 **TypeScript only**；正式客户端仅两端 = **微信小程序** + **官方 React Native App（iOS + Android）**；共享 TS 契约 / API / 可抽出逻辑；RN **不是**小程序交付路径。决策见 [`ADR-技术栈-TS与多端.md`](./ADR-技术栈-TS与多端.md)、[`ADR-客户端-ReactNative.md`](./ADR-客户端-ReactNative.md)。

### 2.1 层级 × 技术 × 版本 × 理由

| 层级 | 技术 | 版本 / 形态 | 选型理由 |
|------|------|-------------|----------|
| 语言方向 | **TypeScript（唯一）** | Node/TS monorepo 目标 | 一套类型贯穿引擎、契约、多端适配层；**禁止新增 Python** |
| 正式客户端 A | 微信小程序 + **Vant Weapp** | 微信原生运行时；`@vant/weapp` ^1.11.7 | 微信内触达；**独立于 RN**；禁止自研设计系统 |
| 正式客户端 B | **官方 React Native** App | TS；**iOS + Android** | 与小程序共享 `api-plans-contract` / 三主卡 IA / 可抽出逻辑；**非**小程序编译路径 |
| Web 原型（冻结） | Vue 3 + Vant 4（CDN） | CDN，无构建 | 快速对外演示；**非生产** |
| 规则引擎（现仓） | Node.js CommonJS | `backend/engine/*.js` | 零依赖可冒烟；**过渡态 → TS** |
| 规则引擎（目标） | **TypeScript** on Node | 迁移后 `backend/engine/` 或 `packages/engine` | 与契约/客户端同语言；可类型化 `Leg` / plans |
| （已删除）历史 Python | — | 原 `search.py` / `score.py` / `export_fe.py` | **已删除**；引擎唯一实现为 `backend/engine/src/` |
| 数据契约 | JSON Schema draft 2020-12 | `docs/schemas/*.json` | Leg / TransferPlay 字段级校验锚点；后续可 codegen → TS types |
| Mock 数据 | 静态 JSON | `data/mock/`、`backend/data/hub-pois.json` | 已拍板纯 mock 可演示 |
| 缓存（默认） | 进程内 Map + TTL | 默认 **15 min**（`DEFAULT_TTL_MS`） | 拍板：不上 Redis，待 QPS/多实例再上 |
| 仓库形态（目标） | **TS monorepo** | 如 `packages/{engine,contracts,mini,app}`（`app`=官方 RN） | 共享契约包；多端同版本消费 |
| 地图/接驳（后续） | 官方/合规 SDK | — | 不自研路网 |
| 密钥 | 环境变量 / 云密钥管理 | — | 密钥不进仓 |

### 2.2 为什么选「TS + 多端客户端 + 规则引擎」

| 问题 | 选择 | 不选的理由 |
|------|------|------------|
| 语言 | 全栈 TypeScript | 双语言（Python+JS）增加边界与 CI 成本；禁止再开 Python 新模块 |
| UI 组件 | Vant Weapp（小程序）；RN App 侧成熟开源组件 | 自研设计系统成本高、拍板禁止造轮子 |
| 出计划 | 确定性 pipeline | LLM 编车次票价不可审计、易幻觉、违反产品原则 |
| 客户端主线 | **小程序 + 官方 RN（iOS/Android）** | 仅此两端为产品交付；Web 原型冻结示意；共享 API/逻辑，禁止各端私造班次；禁 RN/Alita 出小程序 |
| 数据 | Adapter + Schema | 引擎与供应商解耦；mock/真源字段同构可切换 |

### 2.3 许可与迁移成本

- Vant / Vue：成熟开源，CDN/npm 引入成本低。  
- 引擎现仓无外部运行时依赖（除 Node 标准库 + 本地 JSON）；迁 TS / 上云函数或单机 HTTP 成本低。  
- 历史 `backend/engine/*.py` 与根级重复 CJS **已删除**；唯一实现为 `backend/engine/src/`。  
- 真源切换只需新增适配器并注册，**不改** `searchPlans` 消费者契约（§4、§5）；小程序与 RN App 同契约升级。
- **非交付范围**：Windows / macOS / Web / tvOS / Linux、Proton Native、Alita 等社区扩展不是懂行产品承诺（详见 [`ADR-客户端-ReactNative.md`](./ADR-客户端-ReactNative.md)）。

## 3. 核心架构

### 3.1 设计约束（与红线表口径一致）

| ID | 约束 |
|----|------|
| C1 | 不卖票、不做支付/订单/抢票/账号履约 |
| C2 | 出计划仅 ENG-Pipe / ENG-Rule；禁止 FE 本地「编」车次票价 |
| C3 | Adapter 输出必须符合 `leg.schema.json`；缺字段不得用模型补全班次价 |
| C4 | MCT：同站默认 60min、同城默认 180min；不可衔接组合丢弃 |
| C5 | 自动模式默认：**至多 1 次中转**进三主卡候选（指定途经按段数，途经 ≤ 3） |
| C6 | 「怎么玩」仅当 `buffer_hours >= poi.min_buffer_hours`；12 城以外可只显示接驳 |
| C7 | LLM 默认关闭；开启时不得写入 `service_ref` / `price_*` |
| C8 | 降级路径：真源 → 未过期缓存 → mock → 可解释错误；**禁止**降级时编造 |
| C9 | `index.html` 原型冻结：缺陷以小程序为准修复；原型仅安全/文案同步级改动 |
| C10 | 价格时刻展示带「参考」；无实时余票承诺 |

### 3.2 组件形态分类

| 形态 | 定义 | 适用 | 不适用 |
|------|------|------|--------|
| 流水线编排器 | 单入口 `searchPlans` 串起取腿→定链→MCT→POI→打分 | 查询主路径 | 承载 UI、密钥、爬虫 |
| 纯函数规则 | 无 I/O（或只读入参）的 MCT/打分 | 可单测、可重放 | 持有 DB 凭据 |
| 适配器 | I/O 边界，归一为 `Leg[]` | mock / 合规 API | 业务打分、文案产品逻辑 |
| 静态内容表 | 人工维护 JSON | 枢纽 POI、样例腿 | 运行时由模型生成 |
| 前端壳 | 页面状态机 + 适配层 | 展示三主卡/空态 | 枚举换乘组合 |

**新建模块自证准则（满足 ≥3 条才建）**

| # | 准则 | 说明 |
|---|------|------|
| 1 | 有独立失败半径 | 故障不应拖垮整条 pipeline |
| 2 | 有独立契约/Schema | 可单独版本化 |
| 3 | 有独立测试面 | 可单测或冒烟 CLI |
| 4 | 跨 ≥2 消费者复用 | 避免一次性脚本升格为模块 |
| 5 | 红线表可归类 | 归不进则不建 |
| 6 | 无密钥泄漏面扩大 | 不新增明文凭据路径 |
| 7 | 不与现有模块职责重叠 | 重叠则扩展而非新建 |

| 引擎开发 | pipeline / mct / score / 导出 | 卖票履约 |
| 数据内容 | legs mock、hub-pois、合规源短名单（私有） | 改打分公式而不提 PR |
| 小程序前端 | 四页交互、空态、adapt 层 | 在端上枚举 MCT 组合当权威 |
| 运维（后续） | 密钥托管、网关、观测 | 放宽爬取策略 |

### 3.4 协作机制与 Artifact

| Artifact | 本质 | 生产者 | 消费者 | 治理 |
|----------|------|--------|--------|------|
| `Leg` | 分段时刻价真相 | Adapter | pipeline | Schema 必填；`source`+`as_of` |
| `TransferPlay` | 枢纽玩法 | 人工 JSON | pipeline.pickPlays | 独立表，不嵌 Leg |
| `Plan`（buildPlan） | 候选方案 | pipeline | score / 导出 / 前端 | 含 legs、transfers、play |
| `main` 三槽 | 主卡 | score.pickMainCards | API/前端 | cheapest/fastest/balanced |
| `PlansSearchResponse` | 对外契约 | 网关/导出 | FE | 见 api-plans-contract |
| `why_facts` | 模板结构化字段 | 引擎 | 文案层 | 禁止含臆造车次 |

**聚合边界**：一次 `searchPlans` 调用内完成枚举与打分；前端不得二次「发明」腿。小程序开发期可读预导出 JSON（离线固化的一次 pipeline 结果）；正式路径走 API。

### 3.5 MCT（最小换乘时间）

实现：`backend/engine/src/mct.ts`。

| 项 | 默认值 | 说明 |
|----|--------|------|
| `same_station` | **60** 分钟 | 到站名 === 下一腿出发站名 |
| `same_city` | **180** 分钟 | 同城不同站 |
| 无法分类 | `ok:false` | 跨城未衔接，丢弃 |
| 缓冲计算 | `floor((dep_at - arr_at) / 60000)` | ISO 带时区 |

失败路径：整链任一段 `!ok` → 不进入 `plans`（§3.12）。

### 3.6 打分与三主卡

实现：`backend/engine/src/score.js`。**分越低越好**。

| 槽位 | 函数 | 主因子 | 次因子 |
|------|------|--------|--------|
| 最省钱 `cheapest` | `scoreCheapest` | `price_ref_cny` | `duration/1e6` |
| 最快 `fastest` | `scoreFastest` | 门到门 `duration_min` | `price/1e6` |
| 最综合 `balanced` | `scoreBalanced` | 价+时+换乘+单段久坐 | 航班惩罚、comfort、可玩窗口加分 |

综合默认权重（`DEFAULT_BALANCED_WEIGHTS`）：

| 键 | 默认 |
|----|------|
| `price` | `1/650` |
| `duration` | `1/2000` |
| `transfers` | `0.35` |
| `maxLegSitMin` | `1/3000` |

> 综合偏铁路卧铺 + 可玩窗口；空铁更易进「最快」。产品文案层勿暴露「加权系数」工程句（见空态与文案规范）。

### 3.7 定链与 POI 挂载

| 模式 | 定链规则 | 实现 |
|------|----------|------|
| 自动 `auto` | 直达 + 经头部 12 枢纽插 **1** 个中转；可选 `extraHubs` 短途样例 | `searchPlans` else 分支 |
| 指定路径 `user` | `from + vias(≤3) + to` 分段；不再自动换枢纽 | `searchChainCities` |

POI：`backend/data/hub-pois.json`；`pickPlays(hub, bufferMin)` 过滤 `hours >= min_buffer_hours`，按阈值降序取最多 **3** 条。

**12 城（锁定）**：北京、上海、广州、深圳、成都、重庆、武汉、杭州、郑州、西安、兰州、**西宁**（进藏样例不可删）。

#### 3.8.2 方案状态枚举（查询结果）

| 状态 | 含义 | 安全默认 |
|------|------|----------|
| `OK` | `ok:true` 且至少一张主卡 | 展示三主卡 |

## 4. 扩展体系

### 4.1 四类扩展边界

| 类型 | 本质一句话 | 允许条件 | 确定性 | 谁执行 |
|------|------------|----------|--------|--------|
| **Skill（怎么做）** | 导出/适配/运营手册级步骤 | 不改红线 | 流程可重复 | 人 + 脚本 |
| **Policy（何时允许）** | 演示开关、path_mode、缓存 TTL | 产品拍板 | 配置常量 | 配置 |
| **Rule（确定性判断）** | MCT、打分、POI 阈值 | 单测覆盖 | 纯函数 | ENG-Rule |
| **Tool（真正执行）** | `searchLegs`、读 JSON、未来 HTTP 真源 | 权限与密钥边界内 | I/O | ADP / GW |

横切约束：任何扩展不得让 LLM 成为 Rule/Tool 的班次价来源。

### 4.2 Tool 清单

| 名称 | 输入 | 输出 | 权限级别 | 幂等 | 内部组件 |
|------|------|------|----------|------|----------|
| `adapters.searchLegs` | `{from,to,date?,after_at?}` | `Leg[]` | L0 读公开/mock | 是（同参同快照） | train+flight mock |
| `mct.checkConnection` | 两段 Leg | `{ok,kind,buffer_min,required_min}` | L0 | 是 | mct.js |
| `score.pickMainCards` | `Plan[]` | `{cheapest,fastest,balanced}` | L0 | 是 | score.js |
| `pipeline.searchPlans` | `{from,to,date?,vias?,extraHubs?}` | `{ok,main,more,meta}` | L0 | 是（同数据版本） | 编排以上 |
| `src/search-pipeline-demo.ts` | 冒烟 | 打印三主卡 | L0 只读 mock | 否 | pipeline |
| 未来 `train.<vendor>.searchLegs` | 同契约 | `Leg[]` | L2 需密钥 | 视上游 | vendor SDK |
| 未来「去购票」深链 | 站名+日期 | 外跳 | L0 无本站收款 | 是 | 仅 URL 模板 |

**权限级别枚举**

| 级别 | 含义 |
|------|------|
| L0 | 只读本地或公开契约，无密钥 |
| L1 | 可写仓库内数据文件（经 PR） |
| L2 | 持密钥调外部 API（密钥不进仓） |
| L3 | 写用户隐私 / 支付 — **本产品不开放** |

### 4.3 扩展类型判断矩阵

| 能力特征 | 优先实现为 |
|----------|------------|
| 新合规数据源 | ADP-Vendor Tool + Policy(TTL) |
| 新打分维度 | Rule（改 score + 单测） |
| 新枢纽城 POI | DATA-Static + hubs 文档 |
| 口语「便宜就行」 | 可选 LLM-Optional → 映射到已有权重，**不**新编腿 |
| 卖票/会员支付 | **拒绝** |

## 5. 数据访问层

### 5.1 设计动机（挑战）

| 挑战 | 应对 |
|------|------|
| 票源合规与反爬 | 只走授权 API；禁爬 |
| mock 与真源切换 | 同一 `Leg` Schema |
| 价格易变 | TTL + `as_of` + 文案「参考」 |
| 引擎被供应商 SDK 污染 | 双路径：内部 Repository 形函数，外部 Adapter |
| 密钥泄漏 | 集中 env；CR 阻断 |

### 5.2 双路径

```text
ENG-Pipe
  └─ searchLegs()          ← 内部稳定契约（Repository 角色）
        ├─ train.mock / flight.mock     （当前）
        └─ train.<vendor> / flight.<vendor>（后续）
              └─ 合规 HTTP；密钥仅 process.env
```

协议定位一句话：**Adapter 是唯一允许接触外部票务数据的边界；引擎永不持有供应商 SDK 类型。**

### 5.3 职责分离

| 组件 | 职责 | 不负责 | 经协议层 |
|------|------|--------|----------|
| pipeline | 定链、组合、组装 Plan | 调供应商 SDK | 是（只调 searchLegs） |
| score/mct | 纯计算 | I/O | 否 |
| adapters | 取腿、缓存、日期平移 | 打分、POI 文案 | 自身即边界 |
| hub-pois | 玩法内容 | 时刻价 | 文件只读 |
| FE | 展示 | 生成 service_ref | 否 |

### 5.4 降级阶梯（与 data-sources 一致）

```text
真源 API（成功且缓存未过期）
  → L2/L3 未过期缓存
    → 预置 mock（source:"mock"）
      → 可解释错误（NO_LEGS / NO_FEASIBLE）
```

工程现状：直接 mock 夹具 + 内存 TTL 15min；真源按落地顺序切入（产品设计以真源为目标）。

### 5.5 Adapter 原语

| 原语 | 用途 | 返回 |
|------|------|------|
| `searchLegs(query)` | 按 OD 取腿 | `Leg[]` |
| `configure({ttlMs,legsDir})` | 测试注入 | void |
| `clearCache()` | 测试/运维 | void |

受控查询：mock 为文件过滤；未来 SQL/开放数据必须白名单模板，**禁止**组件持有自由 SQL 凭据拼接。

### 5.6 引擎适配规则与引入时机

| 规则 | 内容 |
|------|------|
| 火车优先 | 主路径铁路；航班服务「最快」与空铁 |
| 字段同构 | vendor 输出必须通过 leg.schema |
| 部分成功 | 无航班仍可出铁路方案 |

**引入 Redis / 多实例缓存的量化信号（建议）**

| 信号 | 阈值 |
|------|------|
| 单机 p95 查询（含取腿） | > 3s 且 CPU 闲置于重复读盘 |
| 实例数 | ≥ 2 且缓存命中成为瓶颈 |
| QPS | 持续 > 20（量级示意，上线前再测） |

真源引入：商务短名单私有；公开文档只写「合规 API」。

### 5.7 快照与血缘

- 每条 Leg：`source` + `as_of`  
- 导出 plans：文件路径 + git blame  
- 查询 meta：回显 request、`data_source`、`disclaimer`  

### 5.8 权限模型（精简）

本产品无多租户 PHI；权限维度主要为：

| 维度 | 控制 |
|------|------|
| 代码仓库 | 无密钥；CR |
| 运行时 | vendor Key 仅服务器 env |
| 前端 | 永不嵌入 Key；深链不含凭证 |

预留：capability token 仅在未来 B 端 API 时设计；当前产品不实现。

## 7. 安全与权限

### 7.1 分层安全模型（4 层）

**L1 供应链与仓库**

- 密钥不进仓；env 不提交  
- 禁止依赖来路不明的票务爬虫包  
- CR 检查：无 Key、无爬取代码、无支付 SDK  

**L2 运行时数据**

- Adapter 边界；前端无供应商凭据  
- 缓存键不含密钥；响应可缓存，凭证不可明文落盘进仓  
- mock `source` 明示  

**L3 产品合规表达**

- 全程「参考价/时刻」；不承诺有票  
- 外链购票；本站不收款  
- 免责声明页可触达  

**L4 可选模型面（默认关）**

- 输出过滤：拒绝含车次号/价格覆写的补丁  
- 不进 Leg 写路径  

### 7.2 高风险操作审批链

本系统高风险不在「写病历」，而在「接真源 / 引入爬取 / 接支付」：

```text
提案（PR 说明合规依据）
  → 负责人预览影响（数据用途、是否进仓、是否对用户收款）
    → 批准（仅合规 API / 仍禁止爬取与卖票）
      → 合并 + 密钥注入托管
        → 审计（commit / 变更单）
          → 可撤销：适配器开关切回 mock（窗口：发现违规立即）
```

## 8. 开发模式

### 8.1 总体原则

- **双轨**：轨 A 引擎/数据正确性；轨 B 客户端可演示体验（小程序优先，App 跟进）。  
- 前置依赖：字段契约定稿 → mock 腿/POI → pipeline 冒烟 → 导出 plans → 客户端挂样例。  
- 禁止造轮子（拍板）；优先开源组件。  
- **语言与仓结构**：新代码 **TypeScript only**；目标收敛为 **TS monorepo**（契约包 + engine + mini + app）；引擎唯一实现为 `backend/engine/src/`。

### 8.2 两条轨范围

| 轨 | 范围 | 完成定义 |
|----|------|----------|
| A 引擎 | adapters、mct、score、pipeline、server | `npm run demo` 绿；徐拉等 OD 对得上三主卡直觉 |
| B 客户端 | miniprogram 四页 + 文案规范；App 规划对齐同契约 | DEMO.md 走查 1 分钟可过；App 以共享 API 验收 |

### 8.3 扩展工作流（8 步）

以「新增合规火车源」为例：

1. 判断需要 ADP-Vendor（矩阵 §4.3）  
2. 编写 `train.<vendor>.js` 输出 Leg  
3. Schema 校验  
4. 单测 / 与 mock 对比抽样 OD  
5. PR（无密钥、无爬取）  
6. 负责人审核  
7. 灰度：开关默认 mock，暗流量对比  
8. 监控错误率；异常回滚 mock  

### 8.4 环境与发布

| 环境 | 用途 |
|------|------|
| 本地 | 开发者工具 + `node` 冒烟 |
| 体验版小程序 | stakeholder 演示 |
| 正式版 | 过审后；仍只荐不卖 |

配置约束：README 只列环境变量**名**；`.gitignore` 忽略 env；`project.private.config.json` 不提交敏感项（已存在于仓则避免写入密钥）。

### 8.5 测试与评估

| 类型 | 内容 |
|------|------|
| 单元 | mct 边界、score 选主卡、adapter 过滤 mode |
| 冒烟 | `npm run demo`、各 `src/adapters` CLI |
| 契约 | plans 导出字段 ⊆ api-plans-contract |
| 体验 | DEMO.md 路径 A/B/C；空态走查 |
| 领域评估集 | 热门 OD（徐拉、沪蓉、京广、成渝）人工对「为什么」直觉 |

评估集来源：`backend/data/mock/legs-*.json` + 导出 plans；禁止用模型生成假腿充评估集。

### 8.6 部署架构

**Dev**

```text
开发者机
  ├─ 微信开发者工具 → frontend/miniprogram/
  ├─ node backend/engine/*-demo.js
  └─ 可选 python3 -m http.server（仅看冻结原型）
```

**生产（目标）**

```text
微信小程序 ──┐

             │              └─ adapters（mock 或 vendor）+ 内存/Redis 缓存
```

### 8.7 迭代模式

小步：改契约 → 改引擎 → 重导 JSON → 同步 `frontend/miniprogram/data` → 走查。每阶段 commit；push 前 `git pull --rebase`。
